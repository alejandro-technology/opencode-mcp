# AGENTS.md

Guidance for OpenCode sessions working in this repo.

## Project

`opencode-mcp` — an MCP server (stdio transport) that lets an MCP host drive an [OpenCode](https://opencode.ai) instance and delegate work to its subagents. Built on `@modelcontextprotocol/sdk` + Zod, with real CLI 2 integration via the official `@opencode/client` (`OpenCode.make`) and an owned authenticated server launcher. This source checkout targets OpenCode CLI `2.2.1` with client `2.2.5`; the migration is unreleased.

Task delegation is **asynchronous**: `opencode_start_task` creates a location-scoped session and calls CLI 2 `session.prompt` with a caller-generated message ID. The prompt acknowledgement returns before execution finishes, and the tool returns `task_id` / `run_id` immediately. Status/result are polled separately via `get_task_status` / `get_task_result`, or long-polled via `opencode_wait_for_task` (`mode: "all"` / `"any"`).

## Commands

Runtime, development, and native TypeScript smoke tests require **Node.js 22.18+** (the official client uses `Promise.withResolvers`). CI checks the development suite on Node.js 22 and 24. Package manager is **pnpm** (only `pnpm-lock.yaml` exists). Scripts call `npx`/`pnpx` internally, which works regardless of how you invoke them.

- `pnpm dev` — launch the MCP Inspector against the server via `tsx` (runs TS directly, no build needed). Use this to test tool wiring interactively.
- `pnpm test` — `vitest run` (full suite).
- `pnpm test:coverage` — `vitest run --coverage`. Coverage thresholds are **100%** for lines, branches, functions, and statements (see `vitest.config.ts`) — any uncovered line fails the run.
- Single test file: `pnpm vitest run tests/modules/tools/wait_for_task.test.ts`. Single test by name: add `-t "test name"`.
- `pnpm build` — clean build: `rm -rf build && tsc && chmod +x build/src/index.js`. **This is also the source typecheck** (no separate `typecheck` script). Tests under `tests/` are outside the build; Vitest transpiles them without typechecking.
- `pnpm check:smoke` — typecheck `scripts/**/*.ts` with `tsconfig.smoke.json`, without emitting build files. CI and `pnpm smoke` run this gate separately because scripts are outside the source build.
- `pnpm smoke --contract-only` — real, non-billable CLI 2 startup/discovery/invalid-model-and-agent probe; `--message-id-only` remains an alias, not the old bare-UUID probe. `pnpm smoke` runs the full paid smoke; `OPENCODE_MCP_SMOKE_MODEL` overrides its exact `openai/gpt-6-luna` default. Add `--source` to test the `pnpx tsx` source entrypoint.
- `pnpm lint` — `biome check .` (read-only).
- `pnpm lint:write` — biome check + autofix (lint + format).
- `pnpm lint:format` — biome format only.

pnpm 11 can refuse dependencies published within its minimum-release-age window. Do not disable global supply-chain policy to force an install: wait for the threshold or follow the operator's review policy. Existing local binaries can run offline validation without installing or changing that policy.

## Testing

Every module has a `<name>.test.ts` Vitest suite under the parallel `tests/` tree mirroring `src/` (e.g. `src/modules/tools/start_task.ts` → `tests/modules/tools/start_task.test.ts`; see `vitest.config.ts` `include`). `src/test-utils/fake-mcp-server.ts` provides a fake `McpServer` for testing tool/prompt registration without a real transport. Tests run in a `node` environment; `src/test-utils/` is excluded from coverage. When adding or changing a module, keep its test file at 100% coverage or `pnpm test:coverage` fails.

## Architecture

- Entrypoint: `src/index.ts` — creates `McpServer`, calls `registerTools(server)`, and connects a `StdioServerTransport`. Signal handlers drain check processes before stopping tracked OpenCode servers; an `exit` handler provides best-effort cleanup. Hard kills cannot run these handlers. Its advertised version must match `package.json`; `tests/index.test.ts` checks this.
- All tools live in `src/modules/tools/*.ts`. Each exports a `registerOpencode<Name>(server: McpServer)` function that calls `server.registerTool(...)`. They are wired together in `src/modules/tools/index.ts`.
- Delegation guidance is supplied through MCP server instructions in `shared/instructions.ts`; no MCP prompts are currently registered.
- Registered tool names are prefixed `opencode_` (e.g. `opencode_start_task`); the source filenames are not prefixed (`start_task.ts`).
- `src/modules/shared/` holds cross-tool infrastructure:
  - `opencode-server.ts` / `opencode-server-launcher.ts` — own the CLI child, pass private Basic credentials, probe authenticated server information/location readiness, and verify the listener PID/version. The launcher path follows `.ts` in source mode and `.js` in the build. Do not replace this with the legacy SDK's banner parser or an unauthenticated port/SPA probe.
  - `server-registry.ts` — in-memory server identity, directory, private credentials, permission policy, and close handler; `killAllServers()` reaps tracked children on shutdown. Never expose credentials in tool results.
  - `task-registry.ts` — in-memory `Map<taskId, TaskRecord>` linking tasks to OpenCode sessions and retaining per-run dispatch, report, result, and usage history. `markTaskCancelled()` stamps `cancelledAt`; `cancel_task` calls it only after interruption/queued cancellation is confirmed and `session.active()` no longer contains the session. CLI 2 interrupt acknowledges acceptance before writer cleanup finishes: do not release the lease, finalize the report, or restore selection merely on that ACK. A timed-out cancellation retains protection.
  - `opencode-client.ts` — `clientForServer(id)` / `clientForTask(id)` build authenticated `OpenCodeClient`s from the registries with bounded, abortable requests. `assistantEntries()` reads chronological CLI 2 message pages through `cursor.next`, normalizes assistant content/model/usage, and correlates assistants to the preceding user ID; CLI 2 has no v1 `parentID`. `lastAssistantEntry()` is `.at(-1)` of that, and `sessionParts()` flattens them. Reasoning is not delivered final text. `deriveTaskStatus()` checks `cancelledAt` first and returns `cancelled` before any session lookup, then returns `empty` — not `completed` — when a finished turn has no text and no tool calls, because a completed timestamp says the turn ended, not that it did work. `buildProgress(latest, whole)` reads `text_snippet` / `current_tool` from the **latest** turn but `tool_calls_completed` / `mutating_tool_calls` / `files_touched` from **all turns in the current run**: an agent's edits land in earlier turns while the final turn is usually just "DONE", so evidence read off the last message alone reports `files_touched: []` for a task that rewrote the workspace.
  - `mcp-result.ts` — `jsonResult()` / `jsonError()` helpers that serialize a payload as an MCP text tool result (use these for consistent output).
  - `instructions.ts` — `createDelegateTaskInstructions()` builds the MCP server instructions. It is **async**: it awaits the quota snapshot before returning, so `src/index.ts` awaits `createServer()`. It embeds only the *spend budget* plus the static tier legend — per-model quotas are deliberately NOT repeated here, because `opencode_list_agents` reports them keyed by the real model id. Don't reintroduce a model table: it would be a second, name-keyed copy of data the agent must fetch anyway.
  - `usage-limits.ts` — exports `quotaTier()` (the thresholds live there only), `quotaByModelId()`, which indexes the snapshot by slugified display name so live model ids join onto docs rows (`MiMo-V2.5` → `mimo-v2.5`), `formatUsageLimits()` (source + spend budget, for the instructions) and `formatTierGuide()` (static legend keyed by the exact `tier` values `opencode_list_agents` emits). `opencode_list_agents` uses `quotaTier`/`quotaByModelId` to annotate every model with its quota. Scrapes the OpenCode Go quota table from https://opencode.ai/docs/es/go/ and renders it as the model-selection block inside the instructions. The snapshot is cached on disk (`OPENCODE_MCP_CACHE_DIR` > `XDG_CACHE_HOME` > `~/.cache`, under `opencode-mcp/usage-limits.json`) and refetched at most once every 24h (`OPENCODE_MCP_LIMITS_TTL_MS` overrides the TTL). A failed fetch falls back to the stale snapshot, then to a quota-agnostic paragraph — startup never depends on the network. Model tiers (high volume / balanced / scarce) are derived from the live req/5h numbers, not hardcoded model names, so the block stays correct when OpenCode changes its lineup.
  - `permissions.ts` — adds only a session-level `external_directory` rule, preserving other user tool denies. `startPermissionResponder()` subscribes to CLI 2 events and reconciles pending requests for owned sessions after `server.connected`, including reconnects. `permission.asked.data` uses `action`, `resources`, and `source: { type, messageID, id }`; read/write classification resolves the source assistant tool part, and unknown external operations are rejected. `getExternalDirectoryPolicy()` resolves `OPENCODE_MCP_EXTERNAL_DIR` env var > `OPENCODE_MCP_EXTERNAL_DIR=<policy>` CLI arg > `read-only` default. The boundary is each task's execution directory, including its worktree. External reads use `once`, never persisted `always` approval that would permit later writes to the same directory.
  - `config.ts` — `getMaxToolTimeoutMs()` resolves the server-side clamp for `opencode_wait_for_task` timeouts: `MCP_TOOL_TIMEOUT` env var > `MCP_TOOL_TIMEOUT=<ms>` CLI arg > 300000 ms default. Reads `process.env`/`process.argv` lazily on each call so tests can vary them.
- `run-observer.ts` finalizes runs in the background; `execution-report.ts` captures independent workspace evidence and executes bounded checks; `execution-usage.ts` aggregates direct-message metrics. `workspace-manager.ts` / `git-workspace.ts` manage detached worktrees and explicit cleanup, while `permission-scopes.ts` routes permission responses by server, directory, and registered session.
- Task, server, and workspace ownership registries are process-local; restarting does not restore them. Retained worktrees are not automatically rediscovered. Worktrees are not security sandboxes; checks run with the MCP process user's privileges.

`opencode_list_agents` returns `models.providers[].models` as objects (`{ id, quota }`), **not** plain id strings, plus a sibling `models.quota_snapshot` (`{ source, checked }` or `null`) that distinguishes "this model has no quota row" from "we never got the table". `quota` is `null` for models absent from the OpenCode Go docs; do not hardcode live catalog counts. CLI 2 discovery also returns canonical `agents.all`, whose `name` is the machine ID and `display_name` is the label. `native` / `custom` are retained nominal buckets with `classification: "builtin_ids"`: CLI 2 does not report provenance, and an ID may have been overridden. `models.defaults` reflects the CLI's selected default rather than inventing defaults for every provider.

### Adding a tool

1. Create `src/modules/tools/<name>.ts` exporting `registerOpencode<Name>(server: McpServer)`.
2. Register it in `src/modules/tools/index.ts` (import + call inside `registerTools`).
3. The tool name passed to `server.registerTool` must be `opencode_<name>`; define `inputSchema` with Zod.
4. Reuse `shared/mcp-result.ts` (`jsonResult`/`jsonError`) for results and `shared/opencode-client.ts` (`clientForServer`/`clientForTask`) for SDK access instead of constructing clients ad hoc — other tools rely on the registries staying the source of truth for server/task identity.
5. Add `tests/modules/tools/<name>.test.ts` (use `src/test-utils/fake-mcp-server.ts` to capture the registration) — coverage thresholds are 100%.

## Gotchas

- **OpenCode version support**: CLI `2.2.1` with official `@opencode/client` `2.2.5` was verified with the real contract-only probe and full `openai/gpt-6-luna` smoke, including worktrees, continuation, cancellation, reports, usage, and cleanup. The launcher version guard accepts `>=2.2 <3`, but does not prove other versions work. OpenCode 1.x is no longer supported. The legacy `@opencode-ai/sdk` package, including its `/v2` export, is not the CLI 2 client. Claim compatibility only after real contract and paid smoke gates pass; keep historical incident/changelog entries historical.
- **Verify real wire shapes.** CLI 2 messages use `type`, `content`, and tool parts with `name` / `state`; they do not use v1 `role`, `parts`, or assistant `parentID`. Follow every message page and preserve unknown metrics instead of treating missing data as zero. Permission events use `data`, not v1 `properties`; use a live server or captured fixture when SDK and CLI versions differ.
- **Continuation overrides are temporary.** CLI 2 prompt inputs do not select the primary agent/model; `agents` means mentions. Use `switchAgent` / `switchModel`, retain the prior model's `variant`, and restore only after confirmed terminal execution or definite pre-dispatch rejection. Uncertain dispatch retains its selection and lease. Surface failed restoration and repair it before another continuation.
- **Smoke source vs. worktree paths:** an external source read followed by an ambiguous "edit shared.txt" can make a model patch the original. That write must remain blocked under `read-only`. Name the source as read-only and the edit target as worktree-relative; assert actual file contents rather than accepting the model's success claim.
- **ESM + NodeNext**: `"type": "module"` with `moduleResolution: NodeNext`. All relative imports in `.ts` files must use `.js` extensions (e.g. `from "./modules/tools/index.js"`), even though the source is `.ts`.
- **Build output lives at `build/src/index.js`** (not `build/index.js`) because `rootDir` is `"./"` with sources under `src/`. `package.json` `main`/`bin` correctly point there; keep them in sync if `rootDir` ever changes. `pnpm build` wipes `build/` first and `chmod +x`'s the entrypoint (it has a shebang), and `prepare` runs the build on install.
- **Build scope**: `tsconfig.json` includes `src/**/*.ts` and excludes test files and `src/test-utils/**`, so test helpers are not compiled into the published package.
- Biome: 2-space indent, 100 cols, double quotes, organizes imports on write. `build/` is excluded via both `.gitignore` and biome's `!!**/build` negation.
